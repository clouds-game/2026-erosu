# 持续集成与发布

## 平台与共享代码

- Windows x64、macOS Universal：Godot .NET 原生游戏，附带 .NET 运行时。
- Web：Blazor / .NET WebAssembly，在浏览器本地执行 C#；静态文件可由 GitHub Pages 提供。
- 两端直接编译同一份 `Core/*.cs`，不复制或重写规则。
- `Web/` 只实现 SVG 绘制、界面与浏览器适配。TypeScript 仅处理键盘、指针、失焦、音频和本地存储。

Godot 4 当前不支持 C# 项目的官方 Web 导出，因此网页版本不是 Godot 引擎的 Web 导出，而是共享规则的独立表现层。参考：[Godot Web 导出说明](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html)、[Microsoft GitHub Pages 部署说明](https://learn.microsoft.com/en-us/aspnet/core/blazor/host-and-deploy/webassembly/github-pages)。

## 工作流

`.github/workflows/publish.yml` 在主分支推送、PR、`v*` 标签、手动触发，以及每天北京时间 02:23（UTC 18:23）运行。GitHub 定时任务可能有排队延迟。

1. 执行纯 C# 规则测试，失败即阻止后续构建。
2. Windows 和 macOS 各自在对应的 GitHub runner 上下载官方 Godot .NET 编辑器和模板，验证 SHA-512 后导出。
3. 检查导出包含 C# 程序集，在对应系统无界面启动 120 帧，再打包 ZIP 与 SHA-256 文件。
4. 构建 WASM，设置仓库子路径的 `base href`，上传网页构建产物。
5. 推送 `v*` 标签时，将两个桌面 ZIP 与校验文件上传到对应 GitHub Release。

GitHub Pages 由独立的 `pages.yml` 发布，详见下方的多分支试玩。桌面与 Nightly 构建不会覆盖 Pages。

常规主分支和 PR 构建的 ZIP 在 Actions 的 artifacts 中保留 14 天。版本标签的下载包保存在 Releases 中。

## 滚动 Nightly

主分支推送、定时或主分支手动构建通过规则测试、两个桌面导出/启动检查和 WASM 构建后，更新同一个 `nightly` 预发布。任何必需构建失败时都不会进入发布任务。它不占用 GitHub 的稳定版 Latest 标记，`v*` 正式发布流程保持独立。

- [Nightly 固定入口](https://github.com/clouds-game/2026-erosu/releases/tag/nightly)
- [Windows x64](https://github.com/clouds-game/2026-erosu/releases/download/nightly/chroma-drop-windows-x64.zip)
- [macOS Universal](https://github.com/clouds-game/2026-erosu/releases/download/nightly/chroma-drop-macos-universal.zip)

每次替换同名 ZIP、SHA-256 文件及 `build-info.json`，将 `nightly` 标签移动到实际构建提交，并在说明中记录提交和 Actions 链接。发布前重新校验两个 ZIP 的哈希；发布任务串行执行，不因新主分支推送而中途取消。旧运行的手动重跑不会覆盖编号更新的 nightly。GitHub 资产替换不是跨文件原子操作，下载时如遇校验不符，应等该次发布完成后重新下载。

动作使用固定 commit SHA。Godot 版本从 `ChromaDrop.csproj` 中读取，避免编辑器与 C# SDK 版本不一致。PR 没有发布权限；只有发布任务才申请 Pages 或 Release 写权限。分支通知工作流仅申请 Actions 写权限以触发主分支发布。

## GitHub Pages 首次启用

在仓库 Settings → Pages 中选择 GitHub Actions，然后配置 Actions 仓库变量 `PAGES_ENABLED=true`。初次启用时，GitHub 因私有仓库套餐限制拒绝 Pages。用户随后明确批准将仓库改为公开，现已启用 Pages 和部署变量。网页地址为 https://clouds-game.github.io/2026-erosu/ 。

## 多分支试玩

入口只保留分支选择、实际构建提交链接和游戏。默认选择 `main`，也可切换 `develop20260926`、`experiment1` 或 `lingjiuu-game0`。选择会保存在浏览器中；`?branch=experiment1` 可用于分享，浏览器前进/后退会恢复选择。

| 分支 | 独立游戏地址 |
| --- | --- |
| `main` | https://clouds-game.github.io/2026-erosu/main/ |
| `develop20260926` | https://clouds-game.github.io/2026-erosu/develop20260926/ |
| `experiment1` | https://clouds-game.github.io/2026-erosu/experiment1/ |
| `lingjiuu-game0` | https://clouds-game.github.io/2026-erosu/lingjiuu-game0/ |

- `tools/pages_branches.json` 定义发布分支。`pages.yml` 只在 `main` 上运行，主分支推送或手动触发时重建整个站点。
- 各试玩分支都包含 `pages-branches.yml`，推送时用 `workflow_dispatch` 请求 `main` 的发布工作流。只在 `main` 添加触发器不会监听其他分支，新增分支时也必须安装这份通知工作流并更新其触发分支列表。
- 构建开始时一次解析各分支的完整提交 SHA，分别执行 C# 规则测试和 WASM 构建。每个子目录的 `base href` 指向自己的路径，脚本、字体与运行时不会串到其他分支。
- 所有分支与入口合成一个 Pages artifact 后一次发布；任何分支测试或构建失败都会保留上一份完整站点。不会单独发布某个分支而删除其他版本。
- 整个 Pages 工作流串行运行。部署前复查分支 SHA，构建期间有新提交则跳过本次发布，由新提交触发的排队运行发布最新版本。
- `branches.json` 和各分支的 `build-info.json` 记录实际发布提交。部署后检查入口、提交信息、每个分支的本地化字体、桥接脚本和真实 WASM 文件；Game0 另外检查猫猫、旋转图标、像素界面图片及其来源和许可文件。

`lingjiuu-game0` 的网页版本直接编译同一份 `Core/Game0/Game0Session.cs`，通过 SVG 复用原型已有布局和素材。浏览器适配层保留拖拽、四边猫猫入口、失败投放返回、动画期间冻结计时、75 秒 Lock 和四次投放后的棋盘旋转。网页构建前运行指针捕获、事件顺序、取消、坐标换算和失焦测试。

这里发布各分支的最新成功构建，不保存每个历史提交的独立网站。GitHub Pages 仍使用 GitHub Actions 发布源，不需要另建 `gh-pages` Git 分支。部署始终来自 `main`，符合现有 `github-pages` 环境的分支限制。参考：[GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[工作流事件](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)。

## 本地 Web 开发与发布

```sh
npm ci --prefix Web
npm run build --prefix Web
dotnet run --project Web/ChromaDrop.Web.csproj
```

生产构建与子路径设置：

```sh
dotnet publish Web/ChromaDrop.Web.csproj -c Release -o build/web
python3 tools/prepare_pages.py build/web/wwwroot --base-path /2026-erosu/
```

`interop.js` 是 TypeScript 生成物，不提交；构建或运行前先执行 `npm run build --prefix Web`。网页不依赖服务器端 .NET，不启用线程，因此不需要额外的跨来源隔离响应头。

## 本地桌面导出

```sh
python3 tools/setup_godot.py
python3 tools/export_desktop.py macos --godot /path/to/Godot
```

Windows 上将目标改为 `windows`，使用 Godot .NET 可执行文件路径。Godot 模板下载较大，约 1.2 GB。安装脚本会校验下载并保留本地下载缓存。

## 签名范围

macOS 使用本机构建工具进行 ad-hoc 签名并验证包签名，尚无 Apple Developer ID 或公证凭据；Windows 暂无 Authenticode 签名。当前适合试玩分发，操作系统可能显示开发者验证提示。后续正式发行需配置对应签名凭据。不会把凭据写入仓库。
