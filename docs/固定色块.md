# 固定色块实验

自由模式新增可选的动态障碍，默认关闭；已有谜题不受影响。

## 规则

- 开局随机放置 3 个固定单格。每轮开始时以 20% 概率决定该轮是否有新固定块，
  若有，则提前确定颜色，并显示在预告最前面。本轮普通块锁定、消除和重力结束后，才随机选择位置放入棋盘。
- 平均每 5 个普通块触发一次，但没有固定周期。固定块不会作为可操控的落块。
- 位置从底部 6 行的合法空格随机选择，不覆盖现有块，也不直接组成三消。无合法位置时跳过本次生成。
- 每块仅有一种颜色，按当前颜色配置的权重独立抽取；颜色、位置均由对局随机源决定。
- 固定块参与碰撞与支撑，但不受重力影响。上方普通块可以被它支撑，下方空隙保持开放。
- 匹配仍按边相邻的同色方块对象数量计算。每个固定单格计为 1 块，每个普通四格块也计为 1 块；两者可以混合组成三消。
- 固定块只能通过普通三消移除，使用相同计分规则；移除后上方块按原有重力规则下落，可触发连锁。
- 生成节奏按锁定块数计算，暂停、等候、查询不产生固定块。重开重置计数。
- 相同种子、颜色配置、开关及操作序列可重现生成结果；不同操作会改变可用空间及后续随机结果。
- 开启功能会消耗额外随机数，因此开关不同的同种子对局不保证后续方块序列相同。
- 固定块增加轮廓标记，保留原有颜色辅助符号。桌面和网页的固定块模式使用独立最高分记录（动态障碍版本）。

## 启动

桌面：

```sh
./tools/play -- --anchored-blocks
```

该参数打开自由模式选项面板并预选固定色块，按「开始」后应用；重新开始沿用开关。切换到谜题或三消演示不添加随机障碍。

网页：在游戏地址后加 `?anchored_blocks=true`，例如 `http://127.0.0.1:5000/?anchored_blocks=true`。
省略参数或使用 `false` 即关闭。该参数打开自由模式选项面板并预选固定色块，按「开始」后应用。

无界面引擎：

```json
{"command":"start","mode":"endless","seed":42,"anchored_blocks":true}
```

`anchored_blocks` 必须为布尔值，省略时为 false。谜题拒绝该字段，避免随机改变已设计关卡。
快照的 `state.anchored_blocks` 描述启动开关；固定方块包含 `anchored:true`，普通方块省略该字段。
读取方块时缺省值为 false。轨迹录制与重放包含真实生成结果。

`afterstates` 只模拟可见信息，不泄露或消耗隐藏随机数。若当前预告有固定块，候选快照的 `anchored_spawn_pending:true` 表示结果停在随机位置确定之前；
真实落子再完成随机放置。概率与颜色已公开，候选不会泄露其位置或下一轮随机事件。
因此这些候选不是包含下一随机障碍的精确棋盘。正常对局快照该字段为 false。`incoming_anchor` 表示本轮预告的固定块（无则 null）；
`forecast` 包含该固定块与普通块预告，`next` 仍只包含普通落块。

## 设计边界

本轮是动态障碍实验，不保证随机布局一定可完全清空，也不限制固定块生成稀有色。
稀有色固定块可能长期占用空间；应先观察实际对局再调整数量、分布或颜色约束。
尚未训练或评估 AI 对该机制的适应能力，旧模型未编码固定属性。

## 验证

覆盖固定支撑的顺序无关性、匹配整块计数、移除后重力、300 个种子/颜色配置组合、
默认关闭的随机兼容性、候选落点不泄露随机信息及生成前结果一致性，以及 JSON 查询与非法请求不改变状态。

本地验证：38 个 C# 规则测试、41 个 Python 回归测试通过（含动态固定块轨迹回放）；
Godot 与 WebAssembly 构建通过，并分别检查了实际渲染。
