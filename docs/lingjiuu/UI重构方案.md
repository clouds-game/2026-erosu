# Godot 桌面端 UI 全面重构方案

状态：2026-09-23，Godot 桌面版已实施并完成原生截图核对。本方案取代此前的三栏白色信息板方案；旧 HUD 的布局、样式和控件结构不再参与运行。

## 视觉原则

棋盘是画面中心，左右只保留窄而稀疏的信息轨。玩家先看形状、落点和结果，再看数字；文字只在图形无法说明一次操作时出现。学习关的指引放在棋盘**右侧空白处**，不占棋盘下沿。暂停、完整按键表、语言等低频操作进入独立弹层。

参考棋类游戏截图的“画面即表达”：居中的玩法区域、图形化侧轨、低文字密度；不照搬其棋子和商店界面。整体颜色以用户选定的 Kenney Pixel UI Pack 蓝色展示图为准。三种模式保留同一棋盘位置，但信息轨按模式改变。

## 蓝色配色

| 用途 | 色值与规则 |
| --- | --- |
| 主背景 | 展示图蓝 `#4E7BB2`；Pattern Pack Pixel 纹样只低透明度叠加 |
| 棋盘 | 深蓝 `#284A71`，相邻格用 `#2E527A` 轻微区分；米色 Kenney 九宫格细框 |
| 弹层与信息位 | `#365F91` 蓝色 Kenney 九宫格；弹层遮罩用深蓝透明层 |
| 操作控件 | 米色 `Ancient/tan` 按钮，当前选项用浅蓝色 `Ancient/white`；深墨蓝文字 `#253044` |
| 文字与棋块 | 深蓝底上的文字为暖白 `#F6F1E4`；棋块直接取 Pixel UI Pack 精灵表中的黄、绿、橙、青四色 |

蓝色主背景不承载小号正文；学习关指引放在深蓝信息位中。红色仅作为未来重要状态的点缀，若用于文字则放在米色底上，不直接用红字覆盖主蓝色。

## 游戏屏

| 模式 | 中央 | 左轨 | 右轨 | 顶部 / 底部 |
| --- | --- | --- | --- | --- |
| 学习关 | 当前形状、完整的同色伙伴、目标落点；操作后直接显示消除结果 | 用三个形状位表示“已有两块，等第三块” | 上方暂停；中部一句阶段性指引“第三块接到同色伙伴旁”，其下显示落下键；成功后该指引消失 | 顶部仅关卡编号；底部留空 |
| 挑战关 | 可思考的棋盘与落点 | 剩余步数或目标进度，采用可计数的图形位 | 暂停与按顺序排列的后续形状 | 不放常驻操作说明 |
| 自由模式 | 自动下落棋盘；消除和连锁在棋盘附近短时出现 | 连锁反馈仅在触发时出现 | 暂停与后三个形状 | 顶部分数；底部速度等级 |

学习关右侧指引不是常驻“提示”小字：只在当前教学动作尚未完成时出现，字数保持一行到两行；玩家开始能独立操作后移除。形状、空位和落点承担主要说明。右侧不能容纳文字时调整整屏布局或棋盘比例，不把文案挤回底边。

## 统一资产规则

用户选定 [Kenney Pixel UI Pack](https://kenney.nl/assets/pixel-ui-pack)。官方页面标注 CC0；实际压缩包包含 `16×16`、间距 `2 px` 的透明精灵表，以及 `48×48` 的 Ancient、Colored、Outline 等九宫格贴图。资源包提供按钮、面板、箭头、基础符号和多种色系，可覆盖所有**界面装饰与控件**。

- 所有可见 UI 框、按钮、选择态、图标槽、弹层、进度位均从这套资源裁切或九宫格拉伸；不再混用旧 Kenney UI Pack、手画白卡片或逐控件自制边框。
- 主背景和信息位统一为蓝色；Ancient 米色九宫格只用于按钮和棋盘细框。Colored 四色只进入玩法棋块，不铺成大面积信息面板。
- Godot 导入采用 nearest 过滤，精灵表裁切按资源说明的 `16 px + 2 px` 栅格；九宫格用 `StyleBoxTexture` / `NinePatchRect`，按钮普通、按下、悬停和键盘焦点状态在一套 `Theme` 中定义。控件尺寸按整数倍缩放，检查像素边缘不糊、不裂。
- 棋子使用 Pixel UI Pack 精灵表中的 16px 方块与符号；字体使用 [Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 12px 比例版（OFL 1.1）；外围背景使用 [Kenney Pattern Pack Pixel](https://kenney.nl/assets/pattern-pack-pixel) 16px 无缝纹样（CC0）。三项素材均经用户选择。
- 已存在的其他 Kenney 包可留在工作树中供对照，但新 UI 主屏和弹层不引用它们的图形。声音属于反馈，不属于 UI 图形；是否沿用已有音效在实际试玩时决定。

## 场景结构

1. 新建游戏屏骨架：背景、居中棋盘、左轨、右轨、极简顶部状态各自独立。棋盘占可用区域的首要份额；两侧轨不做等宽大面板。
2. 将模式选择、关卡选择、暂停设置和结算作为同一套 Pixel UI Pack 风格的独立场景。每屏只保留一个主动作；键盘与鼠标均有清楚的焦点状态。
3. 规则层 `Core/` 保持独立；`GameController` 只把局面状态交给展示组件。旧 `GameHud.cs` 的坐标与样式代码退出主流程，不能作为新场景的基础。
4. 用 Godot Asset Library 的 ThemeGen 在 `Themes/pixel_theme.gd` 生成统一 `Theme`，集中管理 Kenney 九宫格、按钮状态、字体和文本层级。局部节点只表达内容和状态。

## 实施顺序与验收

| 阶段 | 交付物 | 判定依据 |
| --- | --- | --- |
| 1. 真实素材静态稿 | 用 Pixel UI Pack 实际贴图排出学习、挑战、自由三种游戏屏，以及暂停弹层 | 三模式一眼可区分；学习关指引在棋盘右侧；无旧白卡片、长文案或底部拥挤区 |
| 2. 场景与主题重建 | 新游戏屏与弹层接入当前玩法状态 | 旧 HUD 布局不再出现；键鼠能完成选关、操作、暂停、重开、继续 |
| 3. 游戏反馈 | 落点、同色伙伴、消除与连锁的视觉反馈 | 静音时仍看得懂因果；动效不遮住棋子边界 |
| 4. 桌面验收 | Godot 原生运行截图和逐模式试玩 | `1040×800` 基准及更小窗口无裁切；中英日文字不溢出；资源许可可追溯 |
