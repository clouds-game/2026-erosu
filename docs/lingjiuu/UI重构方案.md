# Godot 桌面端 UI 重构方案

状态：供确认的方案，2026-09-23。视觉方向已确定为 **A：清爽街机**；主平台为 Godot 桌面。

## 现状与目标

当前 `Scenes/Game.tscn` 只有固定坐标的 `Board` 与 `Hud` 两个节点；`Game/GameHud.cs` 又以硬编码坐标生成控件。换了按钮贴图，屏幕仍是原来的长棋盘加右侧栏。最新原生截图还可见：操作图标尺寸错误、提示文案重复、第一关棋盘大面积留空。这些是结构问题，无法通过继续叠加边框、粒子或小字解决。

目标是让画面一眼回答三件事：**这一局要做什么、当前形状会落在哪里、下一步可能形成什么消除**。分数和连锁在发生时显眼，设置和完整按键说明在需要时可找到。界面文字只保留必要信息，不在棋盘上常驻解释性小字。

## 目标布局

设计基准为 **1040 × 800** 的桌面窗口，棋盘居中。`10 × 18` 格按 `40 px` 为基准，占 `400 × 720`。左右信息区使用容器布局，窗口变窄时依次收起次要信息，棋盘尺寸优先保持可读。

| 区域 | 位置与尺寸（基准） | 放什么 |
| --- | --- | --- |
| 左信息区 | x=32，宽 256 | 模式与关卡名称、一个明确的目标、剩余块数或进度；底部为打开关卡选择的入口 |
| 中央棋盘 | x=312，y=40，400 × 720 | 方块、落点、匹配预示和结算动画；不放常驻提示条 |
| 右信息区 | x=736，宽 272 | 分数与连锁为主视觉；下面是尺寸足够的后续块序列；顶部仅留暂停/设置入口 |

视觉规格：深蓝色棋盘、暖白色信息底、Kenney 蓝色操作色；四个方块颜色保留明显区分。字号分为三层：主要数字/目标、区块标题、辅助状态。用整块外轮廓和每块一个辅助符号区分相邻的同色形状。棋盘背景要安静，消除时才出现强反馈。

## 需要真正重做的界面

1. **游戏屏**：用 Godot 容器和独立场景重建三栏，不沿用 `GameHud.cs` 中的逐项坐标。解谜关显示完整剩余序列；自由模式显示后三块和速度等级。当前方块已经在棋盘上，不再占一个重复的预览卡。
2. **模式与关卡选择**：用独立覆盖层展示“学习 / 挑战 / 自由模式”，注明解谜关可思考后再落块，自由模式持续自动下落。已完成状态和当前关卡在同一处可见，不再用原生下拉列表承载整个导航。
3. **暂停与设置**：独立覆盖层放继续、重开、声音、语言和操作说明。游戏屏上不常驻四五个等权按钮，也不常驻按键提示小字。
4. **胜负结算**：独立覆盖层显示完成目标、分数与连锁结果，以及下一关或重试按钮。它应是一次明确的状态切换，而不是在棋盘上叠文字。
5. **首关教学**：只在需要玩家行动的时刻给一条大而短的指令，并在棋盘上标示相关的完整形状和目标落点。玩家移动后，标示随状态更新；不重复展示相同规则文字。

## 资产与插件

Kenney [UI Pack](https://kenney.nl/assets/ui-pack)、[Input Prompts](https://kenney.nl/assets/input-prompts)、[Interface Sounds](https://kenney.nl/assets/interface-sounds) 和 [Particle Pack](https://kenney.nl/assets/particle-pack) 已下载并核对 CC0，来源记录在 `Assets/Kenney/SOURCES.md`。现有 UI Pack 主要提供按钮与图标，**不能独自定义整屏视觉**；实施前先将真实资产放入两张同局面的静态布局图，检查按钮、面板和方块能否组成一致的风格。若方块贴图或面板仍缺合适资源，再搜索免费成套素材并列候选供选择，不自行生成游戏资产。

[ThemeGen](https://godotengine.org/asset-library/asset/3299) 保留为统一主题与状态样式的工具；主题只维护一套颜色、字体、按钮及弹层规则。动画先用 Godot 内置 `Tween` / `AnimationPlayer`；只有顺序编辑成为实际障碍时，再引入 [Tween Animation](https://godotengine.org/asset-library/asset/4480)。插件负责可复用实现，不替代布局设计。

## 场景与代码边界

- `Scenes/Game.tscn` 改为主 `Control` + 自适应三栏容器；棋盘、左信息区、右信息区独立场景。
- 模式选择、暂停设置、胜负结算各为独立覆盖层场景，保持清晰的层级与输入焦点。
- `GameController.cs` 继续驱动 `GameSession`；规则层 `Core/` 保持独立。`GameHud.cs` 拆成只展示数据、发出操作信号的组件。
- `ThemeGen` 生成的 `.tres` 作为统一视觉入口；不在每个控件构造函数内手工覆盖一遍样式。
- Web 端在桌面端视觉规格定型后再同步，同一规则层继续共用。
