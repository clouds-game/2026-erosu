# 多模式 RL 的训练改进

本轮以 795,049 参数、观察版本 2 的 CNN 为基线。一个检查点适配三种颜色配置与两个可选规则，共十二种模式。
目标仍为每局最多 300 块的存活任务；每次放置奖励 1，达到预算是任务终点，不做终点价值引导。

## 问题与实验设计

上一轮混合训练按局数轮换模式，长局模式贡献更多训练步；累计每模式约 36 局，数据仍少。
此外，大的价值误差可能通过共享网络和整体梯度裁剪影响策略更新。增加网络参数前，先验证采样、更新稳定性与示范数据。

比较以下路线：

- 旧 PPO 继续训练，作为相同步数预算的对照。
- 平衡 PPO：每模式一个独立引擎，每轮每模式采样 64 步；总批量 768，继续训练 61,440 次放置。
- 启发式示范：每模式等量采集真实引擎状态，学习老师给出的合法动作分布，再比较继续 PPO 后的表现。

所有候选从同一已有多模式策略开始。启发式路线额外使用老师数据，不能称为与纯 PPO 相同的数据预算。
训练采样策略动作；评估使用最大概率动作，所有模式权重相同。评估保留每个模式的结果，避免总平均掩盖退步。

开发集固定为每模式 11000000–11000007，选择完成后再使用 12000000–12000019 测试。
历史测试集 10000000–10000019 不用于本轮选择。只训练一个随机种子，不能用评估局数代替训练重复实验。

## 平衡 PPO

本轮训练与评估固定同一份引擎 DLL，SHA-256 为 `6bd8a88e9570fa49790f0dd7cc87a99bc9015b45ed41ccbef44176a08ea3a8cf`。
本地复现实验先设置：

```sh
export CHROMA_ENGINE="$PWD/build/ai/rl-improvement/engine/ChromaDrop.Headless.dll"
```

运行启动器测试会重新构建默认引擎，提交号改变也会通过程序集版本和 SourceLink 改变二进制哈希。
因此新实验应先构建引擎，再复制完整运行目录并固定 `CHROMA_ENGINE`，避免训练中被测试重建覆盖。
训练器拒绝初始化检查点或数据集与当前引擎哈希不符；不要通过直接改写历史哈希跳过检查。

`AI/ppo_balanced.py` 每个模式保持独立的状态、结束标记与价值引导，批量执行神经网络推理。
引擎仍通过 JSON 接收动作和外部 tick；没有复写 Python 物理规则。
GAE 先按时间 × 环境计算，再与同顺序的动作、观察一起展平；一局结束会切断该环境的递推。

更新使用 Huber 价值损失、梯度裁剪、0.2 的策略比率裁剪及目标 KL 0.02。
KL 检查限制后续小批量更新，不能保证最后一次梯度更新后严格低于阈值；日志同时记录最终全批量 KL。
学习率从 0.0003 线性下降至 10%；仅一个更新的小预算测试使用初始学习率。
每轮保存损失、熵、KL、裁剪比例、价值解释方差、梯度范数、实际更新次数与分模式步数/局数。

```sh
.local/rl/bin/python -m AI.ppo_balanced \
  --init-model build/ai/multi-mode-20260928/policy.pt \
  --model build/ai/rl-improvement/balanced.pt \
  --steps 61440 --rollout 64 --seed 46 --threads 1
```

输出沿用原检查点格式，可直接使用 `AI.ppo evaluate` 与 `AI.ppo play`。
为避免覆盖实验，输出路径必须未被使用；每次继续训练创建新的路径与优化器，不是恢复中断时的优化器状态。
训练记录父检查点、代码和引擎哈希；平衡采样使用 7000000–7999999 范围内未用过的训练种子。

## 教师预热与辅助训练

`AI/mixed_imitation.py` 按模式各采集 1,024 次放置，共 12,288 个状态，使用真实引擎给出的合法落点。
同分最佳动作均分标签概率，避免等价旋转产生矛盾监督。训练固定 10 轮，不根据测试结果挑选中间轮次。
记录的数据包含逐样本模式、游戏种子、引擎哈希及采集策略来源，可复用缓存并验证配置。
默认由老师行动；可通过 `--behavior-model` 采集学生访问的状态，再由老师标注，支持后续纠错数据收集。

```sh
.local/rl/bin/python -m AI.mixed_imitation \
  --init-model build/ai/multi-mode-20260928/policy.pt \
  --model build/ai/rl-improvement/imitation.pt \
  --dataset build/ai/rl-improvement/teacher-data.pt \
  --steps-per-mode 1024 --epochs 10 --training-seed 42 --threads 1

.local/rl/bin/python -m AI.ppo_balanced \
  --init-model build/ai/rl-improvement/imitation.pt \
  --model build/ai/rl-improvement/guided.pt \
  --steps 61440 --seed 46 --threads 1 --teacher-coef 0.5
```

辅助训练在 PPO 原有损失上增加老师动作分布的交叉熵，系数 0.5，每个学生实际访问的状态均查询老师。
这样训练集包含学生犯错后的棋盘，而非只有老师擅长的低堆积局面。该路线使用额外标签，属于模仿学习与 PPO 的混合方法。
推理仍由同一个 CNN 独立选择动作，不调用启发式老师，不需要数据缓存；参数量与原策略相同。
行为克隆只监督策略，共享编码器变化后，旧价值头尚未重新拟合；后续 PPO 使用真实回报继续拟合价值。
省略 `--teacher-coef` 即普通 PPO，保持无监督示范的对照路线。

## 提前输入当前颜色

原网络先将棋盘压缩到 128 维，再与活动块颜色等元数据合并。匹配任务需要知道棋盘哪些块与当前块同色，
这个结构可能使有限数据下的学习更难。可选 `--color-conditioned` 在进入第一层卷积前增加一张“与当前活动块同色”的棋盘平面。
该平面由已有颜色通道与活动块元数据计算，没有新增引擎信息或改变 JSON / 观察版本。
只增加 144 个参数，总数 795,193；不是预置落点评分，也不是推理时调用老师。

迁移时新增卷积权重为零，因此初始动作概率和价值与旧模型一致。旧检查点默认关闭，检查点记录开关；
版本 1 升级至版本 2 时，会把已有颜色匹配平面的权重移至正确通道，并保持新规则通道初始为零。

在上述行为克隆命令上增加 `--color-conditioned`，使用新的输出路径即可训练。
对照使用完全相同的 12,288 条示范、随机种子与优化器，分别比较 10 轮和 50 轮。
较长训练检验原实验是否欠拟合；相同轮数的两个模型检验输入结构，而不是把训练量差异归因于结构。

开发集选择 10 轮颜色条件模型作为最后的 PPO 初始化，随后分别继续纯 PPO 与带 0.2 教师辅助损失的 PPO，
各训练 30,720 步，随机种子 47，初始学习率降低至 0.0001。初始化模型仍参加最终候选比较，防止微调后的退步被掩盖。

```sh
.local/rl/bin/python -m AI.ppo_balanced \
  --init-model build/ai/rl-improvement/conditioned.pt \
  --model build/ai/rl-improvement/refined.pt \
  --steps 30720 --seed 47 --threads 1 --learning-rate 0.0001

# 另一组使用新的输出路径，并追加 --teacher-coef 0.2
```

相关实现依据：[PPO 论文](https://arxiv.org/abs/1707.06347)、[PPO 实现细节分析](https://iclr-blog-track.github.io/2022/03/25/ppo-implementation-details/)。

仅做单次训练种子实验。开发集被反复用于比较候选，不能作为独立泛化结论。
带模仿学习和在线教师指导的候选使用了额外标签，因此不能视为与纯 PPO 完全等数据预算的对照。
所有策略共享 12 种模式；不按模式选择不同模型。模型文件仅保存在本地 build 目录。

最终检查点采用颜色条件输入与行为克隆，不是把全部提升归因于纯 PPO。原结构训练 50 轮后，示范动作命中率从 37.25% 升至 84.65%，开发集存活却未提高；颜色条件结构只增加 144 个参数，在同样 10 轮训练下已明显改善泛化。两种 PPO 微调均未超过初始化模型的开发集平均值，因此保留初始化模型。

独立测试中十二个模式的平均存活都提高，达到 100 块的局数从 6/240 增至 96/240，达到 300 块从 0/240 增至 8/240。中位数从 41 增至 88，平均得分从 47086.67 增至 151652.92。仍然只代表一组训练随机种子，不能据此声称策略已稳定解决所有模式。

机器可读的逐局结果、候选预算、模型哈希与选择来源见 [完整报告](../AI/reports/rl-improvement.json)。本地最终模型为 `build/ai/rl-improvement/selected.pt`，795,193 个参数；选择使用的八个开发种子已写入检查点的验证种子记录，后续正式评估会拒绝重用。

```sh
.local/rl/bin/python -m AI.ppo play \
  --model build/ai/rl-improvement/selected.pt \
  --game-mode rare_seven_anchored_fill --seed 12000000 \
  --trace build/ai/rl-improvement/new-replay.jsonl --threads 1
```

现成回放 `baseline-replay.jsonl` 与 `selected-replay.jsonl` 均使用种子 12000000、七色加两个可选规则，逐步复验通过。这个未经挑选的单局中，原策略存活 57 块，新策略 47 块：平均提升不意味着每个种子都获胜。新回放命令应使用未存在的输出路径。

本轮完整 Python 测试 68/68 通过，覆盖合法动作、跨环境 GAE、模式均衡、软标签、颜色条件迁移、旧模型加载与双规则回放。训练和缓存输出均有路径冲突检查，避免覆盖父模型与已有实验。
