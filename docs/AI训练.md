# Python AI 训练

首版目标是自由模式的得分与生存。使用标准库实现交叉熵搜索（CEM），训练线性落点评估器。
无需 GPU、PyTorch 或额外 Python 依赖。它是通过对局反馈调整参数的策略，不是深度神经网络。

## 运行

从仓库根目录执行，Python 3.10+、.NET 8：

```sh
python3 tools/play.py --headless --prepare-only
python3 -m AI.train train --generations 5 --population 12 --episodes 4 --max-pieces 150
python3 -m AI.train evaluate --seed 2000000 --episodes 20 --max-pieces 150
python3 -m AI.train play --seed 2000100 --max-pieces 150
```

默认输出在忽略的 `build/ai/`：`model.json` 保存权重、特征顺序、训练种子和训练历史；
`evaluation.json` 保存随机策略、手写初始策略、训练策略在同一组种子上的逐局结果；
`game.jsonl` 保存单局全部 JSON 请求及响应，可审查、回放或作为以后可视化的数据源。
`play` 当前在 CLI 运行并记录对局，不打开 Godot 窗口。
轨迹使用 [版本化 JSONL 格式](轨迹与回放.md)，可通过 `./tools/play --replay build/ai/game.jsonl`
重演并验证全部响应。
各路径分别由 `--model`、`--report`、`--trace` 指定。

## 架构与时序

- `AI/engine.py` 管理一个持久 C# 子进程，以 JSON 行协议通信，退出时关闭子进程。
- `AI/policy.py` 枚举最多四个朝向及各列的直接落点，提取堆高、空洞、表面起伏、
  落点高度、相邻同色完整块数、相邻异色完整块数。相同块的多个接触边只计一次。
- `AI/train.py` 采样权重、执行对局、选取精英并更新采样分布；每代保留最佳模型。
- Python 只估计落点特征，不复制消除、刚体重力、随机袋、连锁或计分规则。
  旋转、移动、落地、消除与奖励均由共享 C# 引擎实际执行。
- 思考及移动不消耗 tick；硬降后逐 tick 推进到下一块出现或对局结束。
  这训练的是放置策略，不测手速，也不能直接等同于带实时压力的桌面玩家表现。
- 估计器不搜索软降钻洞；堆高时实际旋转修正或水平阻挡可能改变计划落点。
  引擎反馈为准，评估记录 `rejected_actions`，不伪造成功动作。
- 首版只根据当前块和棋盘评估，不读取隐藏随机袋，也不利用后续块搜索；它不主动规划多步连锁。
  模型记录源码摘要，修改规则或特征后应重新训练和评估。

## 训练与评价

每个候选用同一组训练种子，目标为 `平均得分 / 1000 + 平均锁定块数 × 0.1`。
生存项帮助无消除的早期策略获得反馈；正式报告分别给出游戏分数和存活块数。
每代前四分之一（至少两个）作为精英，更新各权重高斯分布，并保留最低探索标准差。
初始策略提供合理起点，训练结果必须与其比较，不能只胜过随机策略就声称学习成功。

评估拒绝与训练重叠的种子；同一组评估种子对比三种策略。`truncated` 表示达到
`--max-pieces` 上限，不能算作自然存活到终局。提高上限可评估长局表现。
少量种子的测试只证明管道可用，泛化强度需更大样本；不得以训练集成绩代替独立评估。
可重复性限定同一源码、Python/.NET 版本及参数；不保证跨运行时版本的 RNG 一致。

设计参考：[Tetris 交叉熵训练研究](https://www.cs.utexas.edu/~shivaram/readings/b2hd-ThierryScherrer2010-b.html)。
已查看 Godot 插件方案；本项目已有不依赖引擎的 JSON 主机，无需为训练引入 Godot 场景或插件。

## 首次训练记录

仓库附带 `AI/models/starter.json` 和逐局报告 `AI/models/evaluation.json`。
模型训练使用种子 42、8 代、每代 16 个候选、12 个训练种子、每局最多 150 块。
可直接运行：

```sh
python3 -m AI.train play --model AI/models/starter.json --seed 3000100
python3 -m AI.train evaluate --model AI/models/starter.json --seed 3000000 --episodes 20 --max-pieces 300
```

独立评估种子为 3000000–3000019，每局最多 300 块：

| 策略 | 平均得分 | 平均锁定块数 |
| --- | ---: | ---: |
| 随机落点 | 1,610 | 18.85 |
| 初始手写权重 | 210,040 | 296.9 |
| CEM 训练权重 | 220,760 | 300 |

训练模型在本样本上比初始策略高约 5.1%；19 局达到上限，1 局在第 300 块结束，
不能据此声称能无限生存。初始策略有 18 局达到上限。训练策略共发生 2 次被阻止操作，
实际对局仍完全由引擎执行。
这只是小样本描述性结果，不是统计显著性结论。更早的三种子试训在另外 20 个种子上
反而比初始策略低 4.3%，因此扩大训练集后，使用全新的种子范围进行本次最终评价。
禁止把反复挑选评估种子的结果当作泛化证据。

示例种子 3000100 的 150 块对局得到 112,400 分、消除 135 块、最高 3 连锁；
实际命令记录可用 `play` 重建。


覆盖真实对局重复性、外部时钟下的进展、空盘估计落点与 C# 的一致性、按完整块统计接触。
