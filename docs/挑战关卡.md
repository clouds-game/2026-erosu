# 挑战 1：蓄势连消

前三关保留为可选「学习」内容；游戏默认进入挑战 1。选择器明确区分挑战、学习和自由模式。既有学习通关存档继续有效，学习最后一关完成后可进入挑战；挑战通关后可重玩。

## 体验目标

玩家面对已摆好的四个完整方块，使用五个固定方块清空棋盘。难点是判断落点、旋转以及其他颜色消失后的支撑关系，而不是跟随一次落下的操作指示。没有自动下落与时间限制。

颜色均沿用现有图案标记：红 / 圆点、绿 / 方框、黄 / 十字。剩余序列完整展示，按从左到右的顺序使用；当前活动块已经在棋盘上。

## 初始棋盘

坐标从左上角 `(0,0)` 起，10 列 × 18 行。数据与规则位于 `Core/PuzzleLevel.cs`，关卡稳定 ID 为 4；学习关卡继续使用 ID 1–3，不因菜单重新分组而改变存档含义。

| 方块 | 颜色 | 格子坐标 |
| --- | --- | --- |
| I | 黄 | `(1,17) (2,17) (3,17) (4,17)` |
| O | 绿 | `(3,15) (4,15) (3,16) (4,16)` |
| T（翻转） | 黄 | `(7,16) (8,16) (9,16) (8,17)` |
| O | 红 | `(4,13) (5,13) (4,14) (5,14)` |

待落序列：**红 S → 绿 L → 黄 O → 红 J → 绿 J**。

## 为什么需要规划

- 初始棋盘稳定，没有预先满足的匹配。
- 前两步之后，每种颜色都只有两个完整方块，因此无论如何摆放都不能消除。至少两步准备是颜色数量保证的，不是隐藏判定。
- 最后一个绿色方块出现前，绿色数量不足三个；全清不可能提前完成。五个方块都需要用到。
- 一种参考解先放四块，再由最后一块触发绿 → 红 → 黄的三波连锁，共 1,800 分。
- 允许其他全清方案，包括提前消除的解法。三连锁不是额外的隐藏通关条件；目标始终只有清空棋盘。
- 提示只建议观察消除后的支撑变化，不直接给落点。

## 作者验证

27 项常规测试覆盖参考输入、三波颜色顺序、计分、全部五块必须使用的数量约束，以及原有学习关卡与自由模式回归。

额外离线分析：

```sh
dotnet run --project Tests/ChromaDrop.Tests.csproj -c Release -- --analyze-challenge
```

该工具调用真实 `GameSession`，枚举在上方旋转、水平移动后硬降的落点，并缓存等价棋盘。此次共分析 145,818 个状态，得到 30,803 条成功放置序列；37,154 个提前消除分支中，34,902 个没有后续成功的直接硬降方案。

**边界：**工具不枚举钻入悬挑下方等软降后再侧移的操作，所以不宣称唯一解，也不把某个分支在此搜索中失败解释为所有输入下均不可挽回。禁止提前全清的颜色数量论证不受该搜索边界影响。实际难度仍需要玩家试玩判断。
