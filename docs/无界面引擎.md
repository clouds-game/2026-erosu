# 无界面引擎与 JSON 协议 v1

纯 .NET 8 控制台程序，与 Godot、Web、测试直接编译同一份 `Core/*.cs`。
不需要 Godot、窗口、资源导入或网络；不复制匹配、重力、计分或关卡规则。

## 启动

推荐使用统一启动器（Windows 使用 `python tools/play.py --headless`）：

```sh
./tools/play --headless
```

自动构建 Release 引擎并启动；构建日志只写 stderr，stdout 始终为 JSON 协议。
构建进程不读取 stdin，已管道输入的命令保留给引擎。无需安装或导入 Godot。
`--headless --prepare-only` 只构建，不启动；无界面模式不接受 `--demo`、`--godot`
或额外游戏参数，使用 JSON `start` 选择对局。

也可分别构建和运行：

```sh
dotnet build Headless/ChromaDrop.Headless.csproj -c Release
dotnet Headless/bin/Release/net8.0/ChromaDrop.Headless.dll
```

构建与运行分开，避免构建日志混入协议。标准输入每行一个 JSON 对象，标准输出每行一个
响应，立即刷新。关闭标准输入（EOF）正常退出。每个进程持有一个游戏实例。

## 命令

```json
{"id":1,"command":"start","mode":"endless","seed":42}
{"id":2,"command":"move","direction":"left"}
{"id":3,"command":"rotate"}
{"id":4,"command":"hard_drop"}
{"id":5,"command":"tick","count":60,"soft_drop":false}
{"id":6,"command":"pause","paused":true}
{"id":7,"command":"state"}
{"id":8,"command":"levels"}
{"id":9,"command":"start","mode":"puzzle","level":4}
```

- `id` 可选，原样回传；其余字段严格验证，拒绝未知及重复字段。
- `start` 重置实例及 tick 计数。自由模式必须提供 32 位整数种子；解谜使用稳定关卡 ID。
- `move` 仅接受 `left` / `right` / `down`，每次移动一格；旋转为顺时针一次。
- `tick.count` 为 0–3600 的整数，每个 tick 调用共享规则的 `Advance(1/60)`。
  `soft_drop` 可选，默认 false，在本次所有 tick 内生效。
- 没有墙钟或后台循环；等候 JSON、查询、移动和旋转不会推进时间。
  硬降仍立即锁定并开始匹配；消除和重力阶段必须通过 tick 推进。
- 批量 N tick 与 N 次单 tick 的最终状态一致。暂停及结束状态遵循共享规则，不推进游戏；
  响应 `ticks` 仍记录外部已提交的有效 tick 数。
- 相同程序版本、种子及命令序列可重放；不承诺不同 .NET 或规则版本之间随机序列相同。

## 响应

字段统一为 snake_case：`protocol_version`、`id`、`ok`、`applied`、`error`、
`tick_rate`、`ticks`、`state`、`events`、`levels`。

`state` 包含棋盘宽高、模式、关卡定义、阶段、暂停及输入状态、分数、消除数、最大连锁、
锁定数、等级、剩余数、消除进度、活动块、落点投影、后续块、静态块及当前消除波。
完整方块包含 `id`、`shape`、`color`、`cells`，格子使用 `x` / `y`。
枚举使用小写字符串；坐标原点在左上角。无活动块时 `active` 和 `ghost` 为 null。

`applied` 用于移动、旋转和硬降；合法但被棋盘或当前阶段阻止时为 false。
`events` 按顺序保留本命令产生的全部消除波（方块、连锁、计分明细），避免批量 tick
越过动画后丢失结算数据。`levels` 仅在关卡目录查询时填充。
错误请求返回 `ok:false` 和 `error`，进程继续接收下一行，不改变已有对局。
状态快照用于观察，不是可恢复的存档（不暴露 RNG、内部计时器或隐藏颜色袋）。

## 验证

```sh
python3 -m unittest discover -s tools -p 'test_headless.py'
```

通过真实子进程验证不随墙钟推进、固定 tick 批处理等价、种子重放、暂停、无效输入原子性、
消除事件、解谜通关和 EOF 退出。CI 先构建引擎再执行测试。
