# 棋盘候选模型与容量诊断

## 问题与设计

原模型为 787,337 参数的 CNN actor-critic。棋盘输入包含颜色及整块内部连接，
但策略头直接输出 40 个动作槽位，必须自己学习旋转、落点、消除和重力之间的关系。

先在固定 256 个教师样本上进行 200 epoch 过拟合诊断。训练集最佳动作一致率达到
100%，独立验证集最终约 9.48%。这说明当前容量可以记住这组样本，但不能由此证明
能够学习长链规划；直接扩容没有得到本次诊断的支持。训练损失没有趋近零是因为
多个等价最佳动作的目标概率均分，目标本身有非零熵。

候选模型改为同一个网络分别评价每个合法动作结算后的棋盘。C# 引擎计算落点、
全部消除与刚体重力；Python 不重复规则。只读模拟只使用已公开预告，不读取隐藏随机袋。
候选输入仍为九通道棋盘、下一活动块及两个已知预告，补充本次分数、消除数量、
终局标志及最佳连锁。额外标量分别按 10000、10、1、10 缩放。

本轮先做候选排序行为克隆：对所有合法候选输出标量，以交叉熵拟合原六特征教师的
最佳动作集合。标量是排序分数，**不是未来回报的 value 估计**；还没有加入 TD、
候选 PPO 或多步搜索。这个阶段检查表示方式是否更容易学，而不是声称已有长期规划。

## 复现

```sh
python3 tools/play.py --headless --prepare-only
.local/rl/bin/python -m AI.overfit \
  --dataset build/ai/imitation/train.npz \
  --validation build/ai/imitation/validation.npz \
  --output AI/reports/cnn-overfit.json
.local/rl/bin/python -m AI.afterstate collect \
  --dataset build/ai/afterstate/train.npz --seed 3000000 --steps 2000
.local/rl/bin/python -m AI.afterstate collect \
  --dataset build/ai/afterstate/validation.npz --seed 4000100 --steps 400
.local/rl/bin/python -m AI.afterstate train \
  --dataset build/ai/afterstate/train.npz \
  --validation build/ai/afterstate/validation.npz \
  --model build/ai/afterstate/ranker-42.pt --seed 42 --epochs 15
.local/rl/bin/python -m AI.imitation train \
  --dataset build/ai/afterstate/train-direct.npz \
  --validation build/ai/afterstate/validation-direct.npz \
  --model build/ai/afterstate/direct-42.pt --seed 42 --epochs 15 --batch-size 8
.local/rl/bin/python -m AI.afterstate evaluate \
  --model build/ai/afterstate/ranker-42.pt \
  --direct build/ai/afterstate/direct-42.pt \
  --baseline build/ai/imitation/warm-42.pt \
  --seed 6000000 --episodes 30 --output AI/reports/afterstate-experiment.json
```

训练与验证按整局种子隔离；采集完整最后一局，所以实际数量可以超过 steps。
每份候选数据同时生成 `*-direct.npz`，确保直接动作模型看到完全相同的局面和标签。
本次训练 2079 局面、验证 417 局面；两模型使用相同 batch size 8、学习率、梯度裁剪与 15 epoch，并按验证交叉熵选检查点。
候选模型每个局面需要多次 CNN 推理，计算预算明显更高；这不是等计算量对比。
对旧 warm PPO 的比较只作背景参考，它使用更多示范与 PPO 训练。
评估使用同一组 30 个新种子，贪心动作、七色规则、每局最多 300 块。

模型和数据存于 build，不提交大二进制。原始诊断和评估 JSON 提交到 AI/reports。

## 本次结果

候选模型 782,433 参数，按验证交叉熵选第 5 epoch；
直接模型选第 12 epoch。以下均为贪心策略，同样 30 个独立测试种子：

| 策略 | 平均存活块数 | 中位数 | 平均分数 | 每步决策耗时 |
| --- | ---: | ---: | ---: | ---: |
| 六特征教师 | 122.17 | 118.0 | 81710 | 0.78 ms |
| 已有模仿 → PPO（seed 42） | 32.60 | 32.0 | 3580 | 0.31 ms |
| 同数据直接动作 BC | 31.37 | 29.5 | 4033 | 0.37 ms |
| 结算棋盘候选 BC | 69.73 | 68.0 | 30930 | 7.33 ms |

候选模型平均存活约为同数据直接模型的 2.22 倍，仍明显弱于教师。全部测试自然终局，
未触及 300 块上限。耗时为本机 CPU 的决策阶段，包含候选查询、JSON 编码与网络推理，
不含实际落块结算；不是跨平台性能承诺。

这是一组模型训练种子与一组小示范集的探索结果，不能据此宣称统计显著或具备复杂
长期规划。两种表示的参数量接近，数据与优化步数配对，但候选模型消耗更多推理与
训练计算，且输入已经由规则引擎完成结算。改善说明显式结算是一条值得继续验证的
方向，不证明“模型足够大”已经解决学习问题。

下一步建议在此表示上增加回报学习与多训练种子复验，再考虑扩容或 Transformer。
当前排序分数尚不能用于多步 Bellman 回报自举。

## 单局轨迹

```sh
.local/rl/bin/python -m AI.afterstate play \
  --model build/ai/afterstate/ranker-42.pt --seed 6000000 \
  --trace build/ai/afterstate/game-6000000.jsonl
.local/rl/bin/python -m AI.trajectory replay \
  build/ai/afterstate/game-6000000.jsonl --render
```

示例局存活 62 块、24000 分，461 个 JSON 请求逐字段回放验证通过。轨迹也记录只读
候选查询，因此比只保存玩家动作的轨迹更大。play 拒绝覆盖已有轨迹。
