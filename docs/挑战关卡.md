# 挑战关卡

游戏默认进入挑战 1。当前挑战组共三关，分别练习延迟连锁、分段清场和多组同时消除；前三个基础关卡保留在「学习」分组。挑战可直接选择，完成前两关后进入下一关，完成第三关后回到挑战 1。

所有挑战都使用固定棋盘、固定序列、无自动下落和全清目标。颜色图案沿用现有定义：红 / 圆点、绿 / 方框、黄 / 十字。剩余序列完整展示，当前活动块已经在棋盘上。

坐标从左上角 `(0,0)` 起，棋盘为 10 列 × 18 行。关卡稳定 ID 为 4–6；学习关卡继续使用 ID 1–3，因此已有通关存档不改变含义。

## 挑战 1：蓄势连消

四个初始方块和五个待落方块组成三种颜色各三个的颜色预算。前两步不可能消除，最后一块出现前也不可能全清。参考解让最后一块触发绿 → 红 → 黄三波连锁。

| 初始方块 | 颜色 | 格子坐标 |
| --- | --- | --- |
| I | 黄 | `(1,17) (2,17) (3,17) (4,17)` |
| O | 绿 | `(3,15) (4,15) (3,16) (4,16)` |
| T（翻转） | 黄 | `(7,16) (8,16) (9,16) (8,17)` |
| O | 红 | `(4,13) (5,13) (4,14) (5,14)` |

待落序列：**红 S → 绿 L → 黄 O → 红 J → 绿 J**。

## 挑战 2：分幕清场

这一关改变节奏：把所有颜色留到最后并不是参考路线。第四步先形成红 → 绿两连锁，腾出的空间让最后一个黄色方块完成收尾。玩家需要同时考虑提前消除后的新地形和最终落点。

| 初始方块 | 颜色 | 格子坐标 |
| --- | --- | --- |
| S（竖） | 绿 | `(0,15) (0,16) (1,16) (1,17)` |
| S | 黄 | `(7,17) (8,16) (8,17) (9,16)` |
| T（竖） | 红 | `(3,16) (4,15) (4,16) (4,17)` |
| S | 红 | `(4,14) (5,13) (5,14) (6,13)` |

待落序列：**黄 Z → 绿 J → 绿 T → 红 O → 黄 T**。

颜色数量保证前两步没有任何颜色达到三个，且最后一块黄色 T 必须使用。参考路线得分 1,200，最高连锁为 2。

## 挑战 3：双线坍落

初始块减少为三个，待落序列增加到六个。前三步后每种颜色都只有两个方块，因此必须继续构筑。参考解保持棋盘到最后一步：黄色支撑先消失，重力随后让红色三块与绿色三块在同一波中分别连通。

| 初始方块 | 颜色 | 格子坐标 |
| --- | --- | --- |
| I | 绿 | `(4,17) (5,17) (6,17) (7,17)` |
| S | 黄 | `(3,16) (4,15) (4,16) (5,15)` |
| Z（竖） | 红 | `(8,16) (8,17) (9,15) (9,16)` |

待落序列：**黄 I → 绿 T → 红 Z → 红 S → 绿 O → 黄 J**。

最后一波虽然同时消除红、绿两组，但仍是一波结算：先消除三个黄色块得到 300 分，再消除六个红绿块得到 1,200 分，总分 1,500，最高连锁为 2。

## 难度原则

- 每关恰好包含红、绿、黄各三个完整方块，通关目标始终是清空棋盘，不增加隐藏评分条件。
- 最后一个待落方块的颜色在此前都只有两个，因此所有给定方块都必须使用。
- 挑战 1 强调连续三波；挑战 2 强调中途结算；挑战 3 强调更长序列和同波多组。
- 提示描述需要观察的关系，不直接给出列坐标。
- 关卡允许多个成功方案，不要求复现参考解。

## 作者验证

常规 C# 测试使用真实 `GameSession` 回放三条参考解，检查最终空盘、锁定数量、分数、连锁次数和每波颜色。测试也检查每关初始稳定、没有预先匹配、颜色预算成立、挑战间继续流程正确，以及学习关卡与自由模式没有回归。

离线分析器枚举从棋盘上方旋转、水平移动后直接落下的方案：

```sh
dotnet run --project Tests/ChromaDrop.Tests.csproj -c Release -- --analyze-challenge 1
```

参数可改为 `2` 或 `3`。挑战 1 分析 145,818 个状态，得到 30,803 条成功序列；挑战 2 分析 171,719 个状态，得到 79,932 条成功序列。挑战 3 的六步分支显著更大，常规验收使用确定性参考回放与颜色约束，完整枚举保留为按需运行的作者工具。

分析器不枚举钻入悬挑下方等软降后再侧移的操作，所以不宣称唯一解。实际难度仍需要玩家试玩判断。
