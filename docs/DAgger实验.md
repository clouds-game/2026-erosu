# DAgger：学习自身失误局面

## 目标

已有候选 CNN 从教师正常对局学习，在 30 个新种子上平均存活 69.73 块，教师为
122.17 块。一个可能的问题是：学习者做出不同动作后，到达教师示范较少覆盖的局面。
本次验证增加这些局面的标注是否比继续训练教师正常对局更有效。

使用 [DAgger 原始论文](https://users.cs.utah.edu/~dsbrown/readings/dagger.pdf) 的数据聚合思路：
让学习者实际执行动作，教师仅标注访问状态的最佳合法动作，不接管动作；把新标注
累积到训练池。本实验使用纯学习者采集，不采用教师/学习者动作混合。

## 配对控制

- DAgger：采集当前模型贪心策略访问的棋盘，教师标注。
- 教师回放：采集教师策略访问的棋盘，教师标注。
- 两组均从同一个 `ranker-42.pt` 初始化，使用相同候选 CNN、学习率 0.0003、
  Adam、梯度裁剪 0.5、batch size 8 与更新次数。
- 每个训练批次包含四个原始示范样本和四个累计新增样本，均有放回随机抽样。
- 每组有 42、43、44 三个微调随机种子，每个种子两轮，每轮保留 600 个新标签，
  执行 100 次梯度更新。最终每模型新增 1200 个标签、200 次更新。
- 两组每个对应轮次的环境种子起点相同，但策略不同，访问的局面与完整对局数量不同。
- 采集完成最后一整局，再只保留前 600 个标签；实际执行块数可能超过 600，完整对局
  结果与全部采集种子均记录。标签预算和优化预算配对，环境交互数量不是严格相同。
- 原始示范与独立验证集保持不变；验证教师一致率仅供观察，不选择检查点。
  导出固定最终更新后的模型，避免以教师正常局面验证集选择 DAgger 检查点的偏差。

三种随机种子控制微调中的批次抽样，环境采集种子也按组隔离。**它们共享同一个
初始已训练模型与原始示范集，因此不是三个从零训练的独立完整流程。**

当前网络仍拟合教师排序，未加入未来回报、TD、PPO 或多步搜索。教师在失误局面上的
建议不保证最优或可恢复；本轮的目的是检验数据分布问题，不宣称解决长期规划。

## 命令

建议在采集原始示范和训练初始候选模型之前，复制一次构建产物并固定路径。若已有模型，
副本必须与其记录的 engine_sha256 一致，不能用新的构建替换旧模型的规则指纹。
副本目录须不存在；完整流程使用同一个副本，普通构建不会修改它。

```sh
python3 -c 'from shutil import copytree; copytree("Headless/bin/Release/net8.0", "build/ai/frozen-engine")'
export CHROMA_ENGINE="$PWD/build/ai/frozen-engine/ChromaDrop.Headless.dll"
```

随后按候选模型文档采集初始示范并训练，再执行：

```sh
.local/rl/bin/python -m AI.dagger train \
  --parent build/ai/afterstate/ranker-42.pt \
  --dataset build/ai/afterstate/train.npz \
  --validation build/ai/afterstate/validation.npz \
  --directory build/ai/dagger \
  --seeds 42 43 44 --collection-seed 7000000 \
  --rounds 2 --steps 600 --updates 100
.local/rl/bin/python -m AI.dagger evaluate \
  --directory build/ai/dagger --seed 9000000 --episodes 50 \
  --report AI/reports/dagger-experiment.json
.local/rl/bin/python -m AI.afterstate play \
  --model build/ai/dagger/dagger-42-round-2.pt --seed 9000000 \
  --trace build/ai/dagger/game-9000000.jsonl
```

train 要求输出目录不存在或为空，避免覆盖完整或部分实验。模型与 `.npz` 数据仅存于
build。manifest 逐模型更新并在全部训练完成后标记 complete；evaluate 拒绝未完成实验、
被改写的检查点、引擎不一致和训练/验证种子重叠。数据包含教师概率标签及实际执行动作，
可以核对采集策略。检查点继承父模型全部训练与验证种子，新增采集种子逐轮累积。

50 个全新测试种子 9000000–9000049 同时用于初始模型、教师与六个微调模型，合计
400 局。报告保留每局完整结果、平均/中位存活、四分位、分数、整块消除率、金色消除
局数、封顶局数和决策耗时。三模型使用同一组测试种子，150 局不能当成 150 个独立
环境样本。原先的 30 局结果不与本轮不同种子结果直接计算提升幅度。

## 二进制一致性审计

本轮训练期间，完整测试中的启动器测试重建了默认引擎目录，更新 Git 版本字符串与
SourceLink。C# 规则文件没有变化，但 DLL 指纹发生变化，评估入口按预期拒绝执行。
恢复原版本字符串与 SourceLink 后，DLL SHA256 与初始训练指纹逐字节相同。
在较新构建录制的 677 请求轨迹也通过原构建逐字段验证。报告保留采集构建指纹变体
和此审计记录，不把它们伪装成始终使用同一二进制。

新增防护会在每局采集和评估前、采集完成后及训练轮次结束检查引擎指纹；发生变化
立即失败，不发布混合构建的数据或检查点。`CHROMA_ENGINE` 支持指定冻结目录里的
DLL，所有 Python AI、数据指纹和轨迹记录均使用同一指定引擎。终端启动器的普通
构建仍可更新默认目录。当前实验的冻结副本存于 `build/ai/frozen-engine`。

## 结果

以下结果使用同一组 50 个新环境种子，每行均有 50 局：

| 策略 | 平均存活块数 | 中位数 | 25%–75% 分位 | 平均分数 | 金色消除局数 |
| --- | ---: | ---: | --- | ---: | ---: |
| 教师 | 133.76 | 133.0 | 94.50–163.50 | 92010 | 11/50 |
| 初始候选 CNN | 67.14 | 65.0 | 54.25–75.75 | 31040 | 2/50 |
| 教师回放 42 | 75.08 | 72.0 | 53.25–86.50 | 37284 | 1/50 |
| DAgger 42 | 74.24 | 73.0 | 62.25–82.50 | 35606 | 0/50 |
| 教师回放 43 | 71.88 | 69.0 | 58.00–82.25 | 34330 | 1/50 |
| DAgger 43 | 76.42 | 76.5 | 60.00–86.50 | 38862 | 1/50 |
| 教师回放 44 | 77.94 | 73.5 | 65.00–87.50 | 40426 | 1/50 |
| DAgger 44 | 71.64 | 68.0 | 59.00–82.00 | 33338 | 0/50 |

三个微调模型的平均存活：教师回放 **74.97**，DAgger **74.10**，
初始模型 **67.14**。相对初始模型分别提高 11.7% 和 10.4%；
DAgger 比配对教师回放低 1.2%。这只是本轮的描述性结果，没有统计显著性结论。

所有 400 局自然终局，没有触及 300 块上限。学习者对教师的采集动作分歧约为四成，
说明确实访问并标注了自身策略的局面。但在当前有限预算下，这些标签没有显示出
超过新增教师示范的优势。三组 DAgger 对配对控制的变化也不一致。

金色表现同样没有持续改善，教师仍明显领先。不能把存活小幅提升理解为学会了复杂
连锁或稀有颜色规划，也不能从单个最好微调种子选择“获胜模型”并当作独立测试结论。

因此暂不把 DAgger 设为默认训练路线；保留作为可复验工具。下一步优先以真实对局
回报训练候选 value，随后尝试有限预告搜索，验证能否超出当前局部教师的能力。
需要把 survival 与 score 分开评估，避免稀有颜色奖励被纯存活目标掩盖。

示例 DAgger 42 在种子 9000000 下存活 76 块、38300 分，677 个 JSON 请求回放验证通过。
原始结果见 `AI/reports/dagger-experiment.json`，含全部逐局数据、采集历史、模型与引擎指纹。
